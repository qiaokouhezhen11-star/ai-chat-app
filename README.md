# AIチャットアプリ

ChatGPTライクなUIで、AIとの会話、ストリーミング応答、ファイル参照を実現したチャットアプリです。  
単に会話できるだけでなく、会話履歴の管理、生成の停止と再送、ファイルを踏まえた回答まで含めて、実務利用を意識して設計しています。

## 概要

ファイル参照・ストリーミング応答・履歴管理を備えた、  
**業務利用を想定したAIチャット基盤アプリ**です。

主な特徴は次の3点です。

- ストリーミング応答で、回答を待たずに途中から読める
- `.txt` / `.md` ファイルを会話に添付し、その内容を踏まえた回答ができる
- 会話履歴をローカルに保持し、一覧・検索・切り替えができる

## このアプリの特徴（差別化ポイント）

- 単なるチャットではなく「業務利用」を前提に設計
- ファイル内容を文脈として扱う設計
- ストリーミングによるUX最適化
- 入力制御・安全性を考慮した実装

## AI設計のポイント

- プロンプトにファイル内容を組み込むことで文脈理解を強化
- 回答の一貫性を保つため、入力構造を一定化
- UXを優先し、ストリーミングを先に実装

## 想定課題

- AIチャットは動いても、長文回答では待ち時間が長く体験が悪くなりやすい
- ファイル内容をもとに質問できないと、業務資料やメモを活用しづらい
- 会話履歴の保存や切り替えがないと、継続利用しにくい
- ファイル形式やサイズの制御が弱いと、使い勝手と安全性の両方に課題が出る

## 解決アプローチ

- ストリーミングレスポンスを逐次描画して体感速度を改善
- アップロードした `.txt` / `.md` の内容をプロンプトへ組み込み、文脈付きで回答
- `localStorage` で会話履歴、選択中会話、使用モデルを保存
- フロントとサーバーの両方でファイル形式・サイズ・入力内容を制御
- 生成停止、再送、続きを生成する操作を同一画面で完結

## 効果

- ストリーミングにより、長文回答でも待機時間のストレスを軽減
- ファイル参照により、文脈を踏まえた具体的な回答が可能
- 再生成・停止機能により、ユーザーの操作性を向上

## 工夫したポイント

### 1. ストリーミングによるUX改善

回答全文を待たずに途中から表示することで、長文回答でも待ち時間のストレスを減らしています。  
生成中は停止でき、停止後も再送や続きを生成できるようにしました。

### 2. ファイル連携を自然にチャットへ組み込んだ

`.txt` / `.md` ファイルを添付すると、その内容を文脈としてAIに渡す構成にしています。  
単にアップロードするだけではなく、ファイル内容を踏まえた回答を返せる点が特徴です。

### 3. 会話の再利用性を高めた

会話履歴を `localStorage` に保存し、一覧表示、検索、切り替え、削除までできるようにしました。  
また、最初のユーザー入力から会話タイトルを自動生成し、あとから見返しやすくしています。

### 4. フロントとサーバーの両方で入力制御を実施

未対応形式やサイズ超過ファイルをフロント側だけでなくサーバー側でもチェックしています。  
メッセージ履歴もそのまま受け取らず、`role` と `content` を整形したうえで OpenAI API に渡しています。

### 5. 送信まわりの安定性を高めた

ストリーミング中の状態管理、二重送信防止、停止後の再送、ファイル付き送信の扱いを整理し、操作がぶれにくい構成にしています。

## 技術的な工夫

### ストリーミング応答の実装

OpenAI API からのレスポンスをストリームで受け取り、チャンクごとにUIへ反映しています。  
これにより、ユーザーは生成途中から内容を確認できます。

### ファイル参照機能の設計

アップロードファイルは `FormData` でサーバーへ送信し、サーバー側で内容を読み取ってプロンプトへ追加しています。  
現在は `.txt` / `.md` に対応し、PDFは未対応として安全に制御しています。

### 会話履歴の管理設計

会話履歴、選択中会話、モデル設定をブラウザに保存することで、ページ再読み込み後も継続して利用できます。  
DBを使わず、チャット体験の完成度を優先した構成です。

### 生成制御の設計

`AbortController` を使って生成停止を可能にし、停止後の再送や続きを生成する処理も同じ画面上で完結させています。  
ユーザーが入力し直さなくても再実行しやすいUXを意識しました。

## 設計上の判断とトレードオフ

### なぜ `localStorage` を採用したか

まずは会話体験とUIの完成度を優先し、フロント単体で完結する形にしました。  
一方で、端末をまたぐ共有や永続化には向かないため、将来的なDB移行余地は残しています。

### なぜ PDF を未対応にしているか

今回の段階では、チャット、ストリーミング、履歴管理、テキストファイル連携の完成度を優先しました。  
未対応機能を曖昧にせず、フロントとサーバーの両方で明示的に制御しています。

### なぜストリーミングを優先したか

AIアプリでは、精度だけでなく待ち時間の体感も重要です。  
そのため、回答品質の議論以前に、まず使いやすい応答体験を整えることを優先しました。

## セットアップ

このリポジトリは `apps/web` 配下がチャットアプリ本体です。

```bash
git clone https://github.com/qiaokouhezhen11-star/ai-chat-app
cd ai-chat-app/apps/web
npm install
```

`.env.local` を作成し、OpenAI APIキーを設定します。

```env
OPENAI_API_KEY=your_api_key_here
```

開発サーバーを起動します。

```bash
npm run dev
```
