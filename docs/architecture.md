# Architecture

## 概要

このアプリは、単一のチャット画面に対して、クライアント側の状態管理とサーバー側のOpenAI API連携を組み合わせた構成です。  
会話履歴はブラウザ内に保存し、チャット送信時のみサーバーAPIを経由してOpenAIへ問い合わせます。

## 全体構成

```txt
apps/web/src/app/chat/page.jsx
  ├─ 入力欄、会話一覧、検索、モデル切り替え
  ├─ 送信、停止、再送、続きを生成
  ├─ localStorageへの保存
  └─ /api/chat へ FormData を送信

apps/web/src/app/api/chat/route.js
  ├─ messages と model を整形
  ├─ file の形式とサイズを検証
  ├─ system prompt / file context を組み立て
  └─ OpenAI API の stream をクライアントへ中継
```

## リクエストの流れ

1. ユーザーがメッセージを入力し、必要に応じて `.txt` / `.md` ファイルを添付
2. クライアントが `FormData` を組み立てて `/api/chat` に送信
3. サーバーがメッセージ履歴を整形し、モデル名を検証
4. 添付ファイルがあれば、内容を読み取りプロンプトへ追加
5. OpenAI API に `stream: true` でリクエスト
6. 返ってきたストリームをサーバーで受け、本文テキストだけを抽出してクライアントへ返却
7. クライアントがチャンクごとに画面を更新

## クライアント責務

- 会話一覧の表示
- 会話検索
- 会話タイトルの自動生成
- 会話の切り替えと削除
- モデル選択
- オンライン状態の表示
- 生成停止、再送、続きを生成
- ストリーミング描画
- ファイル選択と初期バリデーション
- 会話履歴の `localStorage` 保存

## サーバー責務

- `messages` のJSONパース
- `role` / `content` の整形
- 履歴件数の制限
- 選択モデルの許可制御
- ファイル形式とサイズの再検証
- PDF未対応時のエラーレスポンス
- OpenAI API への中継
- ストリーミングレスポンスの変換

## 状態管理

主な状態はチャット画面コンポーネント内で保持しています。

- 会話一覧
- 選択中会話ID
- 入力中テキスト
- 選択中ファイル
- ストリーミング中フラグ
- 選択モデル
- 検索文字列
- 直前送信内容
- 停止した回答内容

永続化対象は `localStorage` に保存しています。

- 会話履歴
- 選択中会話ID
- 選択中モデル

## ファイル連携の考え方

アップロードファイルはサーバーで本文テキストとして読み取り、補助的な `system` メッセージとしてOpenAIに渡しています。  
この構成により、RAGや外部ストレージを使わずに、資料ベースの質問体験をシンプルに実現しています。

## なぜこの構成にしたか

- まずはAIチャット体験の完成度を優先したかった
- DBなしでも履歴管理や複数会話切り替えを成立させたかった
- 添付ファイルを扱うため、送信形式は `FormData` が適していた
- UIの体感速度を上げるため、ストリーミングを優先した
